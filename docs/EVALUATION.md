# Evaluation protocol
Preserve evidence/INITIAL_MODEL_SMOKE_TEST_RESULTS.md unchanged. It is user-supplied external test evidence, not reproduced by this kit. Connectivity passed for all selected models. Spark/Wonder behavior labels reflect the original harness, not a definitive model ranking.

Fix oracles first: domain automotive maintenance, reference datetime/timezone and explicit output schema. Spark misread car service as transport; separate domain error from time-ambiguity detection. Original wording partially acknowledged ambiguity, so require semantic grading rather than brittle phrase matching. Wonder: 11 AM is morning; explicit 08:30 pickup must not be relabeled ambiguous service time. ISO date only a required field after schema instruction. Genuine impossible example: service before 10, pickup after 10:30, pickup required before arrival.

Use initial 20 development scenarios, then freeze 40 held-out multi-turn cases before final prompt tuning. Expand only if time/cost permits. Cases: late constraint, replacement/revocation, bare yes with stale proposal, exact pickup/service distinction, unsupported requests, impossible coupled resources, relative dates/month boundary/timezone, correction after ASR, duplicate webhook, concurrent booking, external slot change, cancellation, human handoff, opt-out and process restart. Human-review expected active constraints and permitted final actions; ambiguity permits multiple correct clarifications.

Compare Spark-only stateful baseline and full ledger/validator agent with same user inputs, model, tool data and constraints. Separately compare Spark versus Wonder extraction on same cases; report routing strategy. Neither baseline may perform unsafe external actions. Both run solely against isolated mock adapter. Do not weaken baseline or remove hard cases after inspecting results; record changes/new eval version. Smoke retests aren't held-out evidence.

Metrics with denominators: active-constraint precision/recall, clarification correctness (necessary/irrelevant), bookings violating confirmed hard constraints, correct abstention, feasible-task completion, stale recovery, duplicate bookings per repeated/concurrent attempts, p50/p95 latency and actual usage/cost per completed/failed conversation. Refusal-only agent doesn't count as success on feasible cases. Zero violations in N tests is not a guarantee. Report raw case IDs/errors/output, model parameters, seed, time, commit and oracle version. No confidence calibration claim.

Invariant tests: transactional resource overlap, approval hash/revision, opt-out job cancellation, no mutation after failed parse, no unauthorized tool or arbitrary URL, secret redaction, signed webhooks and repeated transport. Test end-to-end from voice note when actual WhatsApp configured; otherwise label browser/audio fixture simulation. Synthetic TTS clip tests ASR wiring, not natural accent/noise performance. Consented own recordings and fluent review needed for new language quality claims.
